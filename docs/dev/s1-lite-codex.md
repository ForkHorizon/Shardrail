# S1-lite Codex app-server

S1-lite connects one real `codex app-server` child per Shardrail session. The fake ACP provider stays the default. Codex is selected with `--codex-app-server` and at least one allowlisted workdir (`--codex-workdir` or `--session-workdir`). `--codex-workdir` is the default workdir and is also the first allowlist entry.

The adapter speaks newline JSON-RPC on the child's stdio. It does not pass `capabilities.experimentalApi` (D36). `thread/start` and `turn/start` ask for sandbox `workspace-write`, approval policy `untrusted`, and `approvalsReviewer: "user"`. The first live run used `on-request`: Codex 0.160.0 then applied an in-workspace patch to the test repo without sending any approval request, because `on-request` under `workspace-write` lets the model write inside the workspace and run sandboxed commands without asking. `untrusted` asks before every patch and every command outside Codex's small built-in list of read-only commands (such as `ls` or `cat`), which still run without a card. The daemon journals `approval_routing_rejected` and refuses later turns unless the thread response echoes user routing, the configured cwd, approval policy `untrusted` (an `on-request`, `never`, or granular echo is weaker and fails closed; a `turn/start` response that reports a different policy also fails closed), and a `workspaceWrite` or `readOnly` sandbox whose `networkAccess` is absent or false. A non-boolean `networkAccess` fails closed. `turn/start` in Codex CLI 0.160.0 does not return `approvalsReviewer`; a present non-user value still fails closed, and a missing value keeps the thread confirmation.

Each child is started in its own process group. The mandatory safety `-c` overrides, including `web_search="disabled"`, are appended after any extra config. `--codex-config` accepts only `model` and `model_reasoning_effort`, as a single-line `KEY=VALUE` with a non-empty value. SIGTERM or SIGINT of the daemon kills those process groups. SIGKILL of the daemon does not run that handler. Extension checks finish before the session is recorded. A failed check does not leave a session. A retry stays rejected until the child has reached `process_started` or `approval_routing_rejected`, and a journaled `codex_extensions_rejected` stays rejected without respawning.

Before `thread/start`, a preflight child runs `initialize`, `config/read` with the session workdir, and `skills/list`, then exits. `config/read` does not start MCP servers. The response can contain MCP `env` and header values, so the daemon keeps only each server name and its `enabled` boolean and drops the rest immediately. Those values are not journaled, logged, or stored. The session child gets the safety overrides plus `features.plugins=false`, `features.hooks=false`, `features.apps=false`, `skills.bundled.enabled=false`, `skills.include_instructions=false`, a per-name `skills.config` list that disables every skill the preflight found enabled, and `-c mcp_servers.<name>.enabled=false` for every name `config/read` returned, in addition to the static MCP disables. A name that is not a bare TOML key is quoted. A control character, an empty name, more than 64 names, or an over-long argument fails the session closed. Clearing the whole table with `mcp_servers={}` does not remove configured servers, and `features.mcp=false` / `features.rmcp_client=false` do not either.

After `initialize`, and before `thread/start`, the daemon checks `skills/list`, `hooks/list`, `plugin/installed`, and `app/list`, then `config/read` again. Every `mcp_servers` entry must have `enabled == false`. The journal event `codex_extensions_verified` records `mcp_servers: 0`, which is the count of enabled servers. Any enabled server, any other extension left on, an error, or an unexpected shape fails the session closed: the child is killed, `codex_extensions_rejected` is journaled, and no thread starts. User skills are disabled by name. A `name="*"` selector and path globs do not work, so the daemon does not trust the overrides without that check.

After the thread has started, an `mcpServer/startupStatus/updated` notification at any status, or any other `mcpServer/*` notification or server request, is a policy violation. The daemon journals `codex_extensions_rejected`, interrupts a running turn, refuses later turns, and kills the child. It does not journal that activity as `provider_notice`. `mcpServerStatus/list` is not used as a probe: it starts enabled servers.

If a `fileChange` item completes without an approval request for that item, the daemon journals `approval_routing_rejected`, sends `turn/interrupt`, and refuses later turns on that session. This only detects a bypass after the patch is on disk; the approval policy is the prevention.

Command and file-change approval requests become daemon approval cards. A limited client can allow once or deny. Those map to Codex `accept` or `decline`. `acceptForSession` is never sent. Timeout, disconnect, and unknown server requests fail closed. Unknown methods, including user-input, elicitation, and permission grants, get JSON-RPC `-32601` and a `provider_request_refused` journal event. An `mcpServer/*` request still gets `-32601`, and then the session stops as a policy violation instead of recording `provider_request_refused`.

A limited browser may send `turn.start` and `turn.interrupt` on an existing session. It may create a session only when enrollment granted `session.create` (`client enroll --label browser --allow-session-create`). The workdir has to be an exact allowlisted path. Full clients stay on the allowlist when they name a workdir, and otherwise use the first allowlisted directory. The main screen shows **New session** only for a browser that has the capability. The prompt draft belongs to the selected session, stays in the field when the command is rejected, and clears when that prompt's `command_accepted` arrives.

## Try it

`scripts/dev-try.sh` is the way to try this. It builds `shardraild` and the S5 assets, starts the daemon on `127.0.0.1:9731` with a temporary data directory and `--no-file-log`, enrolls a browser with `--allow-session-create`, and prints the URL and the one-time enrollment code. It does not open a browser. The daemon is started with `--exit-with-stdin` on a pipe the script holds open. Ctrl-C, SIGTERM, SIGHUP, and a normal exit run the cleanup trap: the daemon stops, its Codex child is killed with the process group, and the temporary data directory is removed. SIGKILL of the script, or the terminal closing in a way that drops the pipe without a catchable signal, still closes that pipe. The daemon then exits on stdin EOF and kills its Codex children. It cannot remove the temporary directory in that case, because the script is already gone. This uses the Codex login already on the machine. Do not pass an API key.

The default session workdir is `spikes/s1-testrepo` inside the Shardrail checkout. The script finds that checkout with `git rev-parse --git-common-dir` from its own directory, so a worktree resolves to the main repository. Override the workdir with `SHARDRAIL_SESSION_WORKDIR` or `--workdir`. The daemon refuses `/`, `$HOME`, the checkout, and every worktree whose git common dir is that checkout. `spikes/s1-testrepo` stays allowed because it has its own `.git`. The checkout path is compiled from the same git command at build time and can be overridden with `--shardrail-root` or `SHARDRAIL_REPO_ROOT`. A macOS firmlink spelling such as `/System/Volumes/Data/Users/...` is the same directory and is refused the same way. The `chdir-fd` helper opens the admitted path itself with `O_DIRECTORY|O_NOFOLLOW`, checks the device and inode against the directory the daemon pinned, then `fchdir`s and execs. A swapped path does not match, so the child refuses to start and the failure is journaled. The helper closes its directory fd before exec. The daemon does not clear `FD_CLOEXEC` on the pinned fd.

```sh
scripts/dev-try.sh
```

`--dry-run` prints the commands. `--port` or `SHARDRAIL_TRY_PORT` changes the port (default 9731). `--codex` or `SHARDRAIL_TRY_CODEX` selects the Codex CLI. `--skip-build` or `SHARDRAIL_TRY_SKIP_BUILD=1` reuses a binary and assets that are already built. The script refuses to start, including for `--dry-run`, when that port is already in use or when `codex` is missing. Reasoning effort is `low`.

Open the printed URL, review the fingerprint, enter the enrollment code, choose the workdir, and press **New session**. Then use **Send prompt**, **Allow once** or **Deny**, and **Interrupt**. Reset the test repo before a run you care about:

```sh
git -C spikes/s1-testrepo reset --hard 1bb8838
git -C spikes/s1-testrepo clean -fdx
```

Run those from the main Shardrail checkout.

## Live smoke

`scripts/s1-lite-live.mjs` is the checked run. It refuses to start unless `SHARDRAIL_S1_LIVE=1`. Before `git reset` or `git clean`, it requires `s1-testrepo` itself to be a directory rather than a symlink, `.git` to be that repo's real git directory rather than a symlink or gitdir file, no remote, and a git directory that is not Shardrail's. `git rev-parse --verify 1bb8838^{commit}` must succeed first. Reset uses that full hash, and HEAD must equal it afterward. A parent directory may be a symlink. The script starts the daemon on `127.0.0.1:0` with a temp data directory, `--no-file-log`, and the test repo on the workdir allowlist. A full socket client only watches the journal. A headless Chromium browser, enrolled with `--allow-session-create`, creates the session with **New session** and sends the prompt. The run denies the first approval, then allows each later approval once (at most 8, then denies) until that turn finishes. It fails if extension verification was not journaled, if extensions were rejected, if `codex_extensions_verified` is missing `mcp_servers: 0`, if any journal event contains `mcpServer/startupStatus/updated`, if a `provider_notice` method starts with `mcpServer`, or if any journaled command, approval, item, or file path references `~/.codex`, `/.codex/`, `~/.agents`, or `/.agents/`. The result file records the verification event, the enabled MCP count, the preflight log lines, the journaled checklist rows, and the host banner. The run fails when a row the daemon marks `verified` has no source or check time, and when the banner still says “approvals not protected” while sandbox, bypass, and routing are verified. The checkout and `spikes/s1-testrepo` paths come from `git rev-parse --git-common-dir` in the script's worktree. If the model stops after the denial without asking again, it sends one short follow-up prompt and allows its approvals the same way. It then interrupts a second turn after the first new journaled `agent_message_chunk`, and writes `s1-lite-result.json`, `s1-lite-result.md`, and `daemon.log` under `S1_RESULT_DIR`. The transcript virtualizes rows, so that journal event is the delta signal. Any approval routing rejection, including a file change applied without an approval request, fails the run. `S1_RESULT_DIR` must be outside both Shardrail checkouts or exactly `spikes/reviews19/live-1`. The script's hard timeout is 15 minutes. On 2026-10-25 a live run with Codex 0.160.0 passed: one command denied, five approvals allowed once (including the `calc.py` file change and `python3 -m unittest`), and the second turn interrupted.

```sh
export SHARDRAIL_S1_LIVE=1
export S1_RESULT_DIR=/tmp/s1-lite-result
node scripts/s1-lite-live.mjs
```

Headless Chromium must be available as Playwright's `channel: 'chromium'`. The script runs `npm ci` in `apps/s5-prototype` when `playwright-core` is not installed, and `npm ci` in `packages/client` when `@noble/ed25519` is not installed there, then builds assets and `shardraild`. The client import needs those packages beside `packages/client`; `NODE_PATH` does not apply to ESM.

## What the automated tests cover without Codex

`crates/shardraild/tests/codex.rs` drives `tests/fixtures/fake_codex_app_server.py`. The fixture follows the pinned schema in `tests/fixtures/codex-app-server-0.160.0/` (generated by `codex app-server generate-json-schema` for CLI 0.160.0, without experimental methods). The happy-path trace is checked against that schema with an in-repo draft-07 subset validator. The tests check the spawn overrides, initialize without `experimentalApi`, thread and turn parameters, fail-closed reviewer, approval-policy and sandbox echoes, a replayed on-request auto-write (`tests/fixtures/codex-0.160.0-on-request-autowrite.jsonl`) that must interrupt and block the session including `readOnly` with `networkAccess: true`, redaction of a high-entropy secret, deny then allow-once, no `acceptForSession`, unknown-request refusal, interrupt, child crash, approval timeout, disconnect during an approval, an invalid turn `session_id` that rejects without dropping the socket, a refused MCP `--codex-config`, a failed `session.create` retry, and SIGTERM killing the child process group. Recorded Codex 0.160.0 traces check that plugins, hooks, apps, and skills are disabled before `thread/start`, and that the session argv disables every MCP server name returned by `config/read`. The fake child can leave an extension enabled, leave an MCP server enabled, fail `config/read`, keep a hook, or fail a list call, and each of those must fail closed with no thread. After the thread starts, an MCP startup notification or an `mcpServer/*` request stops the session, interrupts a running turn, and rejects a later turn. A `config/read` decoy in an `env` field must not appear in the journal, the daemon log, or the trace. Replacing the workdir path after the pin is journaled and does not start Codex. The fake lists `/dev/fd` and no descriptor may point at the workdir. Closing the daemon's stdin when it was started with `--exit-with-stdin` stops the daemon and the fake child. `scripts/dev-try.test.mjs` starts the try script against that fake on a free port, creates a session so the fake Codex child is running, and checks that SIGINT, SIGTERM, and SIGKILL of the script stop that child and the daemon.

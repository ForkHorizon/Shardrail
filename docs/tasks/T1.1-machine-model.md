- **Established Facts**:
  - `crates/shardraild` connects to relay servers via `RelayDialer` (`crates/shardraild/src/relay_dialer.rs`), registering with role `ConnectionRole::Daemon { machine_id, client_id }`.
  - The relay tracks online daemons by `machine_id` and pairs incoming browser connections (`discoverRelayMachines`, `connectBrowserRelay`).
  - Machines host multiple agents in both CLI and GUI forms (`AgentForm::Cli`, `AgentForm::Gui`).
- **Unknowns / Hypotheses**:
  - Non-blocking agent probe timeouts prevent slow external CLI inquiries from blocking daemon connection startup.
  - JSON schema export and TypeScript contract generation remain deterministic with zero schema drift.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Define canonical data models in `crates/protocol`: `AgentForm`, `DiscoveredAgent`, `MachineInfo`, `MachineStatus`.
  - Export schema via `crates/protocol/src/bin/export-schema.rs` to `schema/contracts.schema.json`.
  - Generate TypeScript contracts in `packages/contracts/src/generated.ts` via `json2ts`.
  - Re-export schema models and extend `RelayMachineInfo` in `packages/client`.
  - Implement discovery engine in `crates/shardraild/src/agent_discovery.rs` (hostname resolution, PATH and fallback probes, macOS Info.plist version extractor).
  - Wire discovery engine into daemon startup and `RelayDialer` registration handshake (`OutboundHello`).
  - Update mock relay (`crates/shardraild/tests/common/mock_relay.rs`) to store and broadcast machine metadata.

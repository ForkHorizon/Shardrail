- **Established Facts**:
  - User-level services (`launchd` on macOS, `systemd --user` on Linux) do not require `sudo`/root privileges and run under the user's interactive session, inheriting user environment, agent paths (`codex`, `claude`), and SSH/developer keys.
  - Standard configuration and state live in `~/.shardrail` (or configured `--data-dir`): `config.json`, `enrollment.json`, `keys/`, `storage.sqlite3`.
  - Logging standard: `$DATA_DIR/logs/shardraild.log` with rolling file appender (5MB max size, 3 backup generations) implemented in `crates/shardraild/src/daemon_log.rs`.
  - In-place binary update: writes to a staging file (`shardraild.new`), enforces 0755 permissions, verifies `--version` executable sanity, atomically replaces the binary via `fs::rename`, and triggers service restart without altering state or databases.
- **Unknowns / Hypotheses**:
  - Service management subcommands can be executed directly by the binary (`shardraild service install|uninstall|start|stop|status`) across both platforms without external runtime dependencies.
  - Automated installer script (`scripts/install.sh`) can work seamlessly in both local build setups (`--local-bin`) and remote release downloads via GitHub Releases API or `gh` CLI.

## 2. Design & Acceptance Criteria
- **Scope & Changes**:
  - Native service manager module (`crates/shardraild/src/service_manager.rs`) implementing `service` subcommands:
    - `install`: generates and writes `com.forkhorizon.shardraild.plist` on macOS or `shardraild.service` on Linux; registers with launchd/systemd.
    - `uninstall`: unloads and deletes service definitions.
    - `start`: boots or resumes background service (`launchctl kickstart -k` / `systemctl --user start`).
    - `stop`: stops background service (`launchctl kill SIGTERM` / `systemctl --user stop`).
    - `status`: inspects service status, PID, and unit configuration.
  - In-place updater (`crates/shardraild/src/update.rs`) implementing `shardraild update`:
    - Auto-detects platform OS (`darwin`/`linux`) and architecture (`arm64`/`x86_64`).
    - Downloads release binary from GitHub release assets (supporting token auth if private or rate-limited).
    - Validates execution via `--version` on temporary download file.
    - Atomically replaces current executable via `fs::rename`.
    - Automatically signals service restart via `service_manager::service_restart()`.
  - Standalone automated installer script (`scripts/install.sh`):
    - Downloads latest or tagged release from GitHub, or copies local binary (`--local-bin`).
    - Installs into `~/.local/bin/shardraild` (or user-specified `--bin-dir`).
    - Automatically configures background service autostart.
    - Supports optional hub pairing parameters (`--relay-url`, `--relay-machine-id`, `--relay-client-id`, `--relay-token`).
  - Integration and unit tests (`crates/shardraild/tests/service_cli.rs`, `service_manager.rs`, `update.rs`).
- **Acceptance Criteria**:

  - In-place updates preserve all user state in `~/.shardrail` (or configured directory) without file modification or database migrations.
  - Daemon startup and discovery models strictly adhere to `crates/protocol` contracts.
